# 90 / 30 FPS 联机研究记录

日期：2026-10-04。本文属于 `research/cross-fps-lan-20261003` 的实验记录，不改变公开 `v0.2.1` 的验收结论。

## 候选修改

原实现提高共享派生浮点 FPS 后，三个运动器高度斜坡路径仍会读取该浮点值。原版以 `30 × 0.5` 得到 15 个逻辑步；90 FPS 下会变成 45 个逻辑步。这些计数由逻辑更新消费，不能使用本机显示频率决定长度。

候选修改在高于原版帧率、且启用共享 DER_FPS 修改时，自动要求三处高度读者使用 DLL 的逐位 `30.0f` 常量。无需额外开启 SIMPIN 位。三处完整特征、原操作数及常量全部预检，挂起其他线程后再次复核；写后与安装结束时复读；任何失败整体回滚。30 FPS 下不增加这些写入，SIMGATE 仍默认关闭。

这只修复已识别的三个读者。对象销毁与第六阶段之间的调用顺序、ModelCondition、迷雾、其他共享时间读者仍有独立风险。它不是跨帧率联机安全声明，也没有突破 90 FPS。

## 已有验证与限制

候选通过既有调度、加载、导出、特征及便携构建检查。私有菜单预检确认：90 FPS 的三处操作数均指向同一个逐位 30.0 常量并在采样期间保持；30 FPS 的三处完整原指令保持。候选 DLL 摘要为：

```text
0c0e88a7ba50d6130c493df0acd6ff91e1fe381481bed0bc7ba49d362d063a02
```

随后进行了八轮同机双进程局域网空闲对照。两端均使用私有六槽诊断 DLL，原生 30 指没有加载 FrameLab 的端点，不能推广为没有诊断 DLL 的普通玩家或跨机器验证。

| 对照 | 观察 |
| --- | --- |
| 原生 30 / 原生 30 | 两轮有限空闲 CRC 匹配；有并行 GPU 训练负载时实际逻辑率下降 |
| 候选 90 / 原生 30，A 房主 | 有限空闲 CRC 匹配；高 GPU 负载一轮约 3.9 Hz，低负载一轮约 15 Hz |
| 候选 90 / 原生 30，B 房主 | 有限空闲 CRC 匹配；同一局训练释放资源后，逻辑恢复约 15 Hz，getter 约 90 / 30 Hz；早期依赖探针失败仍保留 |
| 候选 90 / 候选 90 | 有限空闲 CRC 匹配，逻辑约 15 Hz，getter 约 90 Hz |
| 候选 90 / FrameLab 30，A 房主 | 有限空闲 CRC 匹配，逻辑约 15 Hz，getter 约 90 / 30 Hz |
| 候选 90 / FrameLab 30，B 房主 | 状态读取失败导致测试停止；此前匹配的有限 CRC 不使整轮成为通过 |

正常负载下的 getter 频率只是客户端更新调用率，没有测量 D3D Present。自然 CRC 是游戏原有 lite/轮转模式，不能替代所有对象、完整逻辑状态的逐帧比较。上述八轮是空闲地图，尚未覆盖生产、建造、技能、攻击、死亡与大量单位。

## 诊断发现

历史观察器把 Object 的 pending XYZ 和偏移 `0x236` 的四字节一起比较。原生消费路径实际读取 `BYTE 0x236`，只有它非零时使用 pending XYZ；对象构造会清零该字节，而 pending XYZ 可能尚未初始化。历史原始差异保留，但无效缓存差异不能直接称为模拟分歧。新的比较按有效字节处理。

为动作验证准备的第二版诊断工具使用原生客户端输入流、原生类型化参数与本机玩家身份校验，观察两端自然执行入口与实际对象状态。它没有通过 Lua 直接修改模拟状态，也不强制调用 CRC。其首轮原生 30 / 30 在状态文件访问失败时按原阈值停止；两端仅有两个公共 legacy CRC 点，跨度 450 帧。停止后发起过生产命令工具调用，但在写请求文件前因进程已经退出而拒绝；游戏日志没有该请求的解析、入队或执行确认。失败证据保留，不能算作动作或联机验收通过。

该轮同时确认初始单位实际上是盟军与苏联建造场，生产模块有两个不同的原生 key。字段和类型必须从真实模块确认，不能把旧命名或猜测值当作技能、生产就绪或生命值。

## 原生 30 / 30 动作基线

第三版私有诊断使用按 PID 与创建时间区分的状态文件互斥锁，以及一次 Win32 共享读取；保留实际 API 错误，不重试或放宽原有新鲜度条件。2026-10-04 的首轮原生 30 / 30 动作基线正常结束，原持有句柄停止错误为空。两端均未安装 FrameLab。

| 原生命令 | 双方共同执行帧 | 实际观察 |
| --- | --- | --- |
| 建造场 237 自施法打包 | 58 | 后续双端见盟军 MCV 239 |
| MCV 239 移动 | 2448 | 126 次矩阵位移，4707 个共同逻辑帧的有限投影相同；最终停在目标附近 |
| MCV 239 自施法展开 | 7158 | 未观察到展开效果，仍记录为无效果的请求 |
| MCV 239 位置与角度施法展开 | 9155 | 后续双端见建造场 240，239 消失 |
| 建造场 240 排队电厂 | 10781 | 唯一匹配节点、进度 100、已支付 800；原生 READY 返回值仍为 UNKNOWN |
| 建造场 240 放置电厂 | 13446 | 双端出现电厂 241，实际位置相同，已核实生命值 1000 / 1000 |

六条命令在双方原生执行器均有唯一、类型化参数一致的入口。进入执行器并不等于效果完成；自施法展开的无效果记录没有被另一次位置施法的成功覆盖。

本局自然 lite CRC 有 344 个共同 metadata 点、跨度 15435 逻辑帧，未记录差异。直接计数器给出约 15.15 Hz 逻辑与 30.30 Hz 客户端 getter；这些数值仍不是 Present 帧率。独立只读观察器仅覆盖后半局，其结束时遇到游戏已退出的错误，原 ERROR footer 保留。严格同帧同阶段公共样本数为零，不能将较弱的同帧异阶段投影比较称为严格状态通过。

另发现旧输入比较器用进程内 Object 指针作为跨端键。新分析改用 `(logic frame, actor ObjectID)`；11424 项双方实际存在对象的有限投影相同，21759 项双方缺失占位另行记录，不算对象状态一致。双方 BYTE `0x236` 为零时的无效 pending XYZ 原始差异也保留。

这轮支持部分原生动作的入口及有限对象效果，尚未覆盖普通单位生产、攻击、伤害、死亡、90 / 30 动作混用或完整模拟状态。它不能作为候选联机安全声明。

## 后续验收

继续在原生 30 / 30 完成自动生产与战斗场景的正控。后续分别覆盖候选 90 / 原生 30、候选 90 / FrameLab 30、房主交换和同帧率对照；比较执行帧、玩家、参数、生成单位、位置、真实生命值与自然 CRC，增加掉帧、后台和资源负载场景。每个结论都需有非空覆盖。

公开 0.2.1 与该候选分别保存。实验构建不应以相同版本号替换公开发行物；达到动作、状态和实际呈现率验收后，再决定下一次发布。
