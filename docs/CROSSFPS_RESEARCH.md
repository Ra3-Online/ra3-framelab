# 90 / 30 FPS 联机研究记录

日期：2026-10-04。本文属于 `research/cross-fps-lan-20261003` 的实验记录，不改变公开 `v0.2.1` 的验收结论。候选工件与公开发行物分别保存。下文区分自然执行入口、有限对象效果、严格状态比较、自然 CRC 和实际呈现测量；其中一项有记录，不代表其他项通过。

## 候选修改

原实现提高共享派生浮点 FPS 后，三个运动器高度斜坡路径仍会读取该浮点值。原版以 `30 × 0.5` 得到 15 个逻辑步；90 FPS 下会变成 45 个逻辑步。这些计数由逻辑更新消费，不能使用本机显示频率决定长度。

候选修改在高于原版帧率、且启用共享 DER_FPS 修改时，自动要求三处高度读者使用 DLL 的逐位 `30.0f` 常量。无需额外开启 SIMPIN 位。三处完整特征、原操作数及常量全部预检，挂起其他线程后再次复核；写后与安装结束时复读；任何失败整体回滚。30 FPS 下不增加这些写入，SIMGATE 仍默认关闭。

这只修复已识别的三个读者。对象销毁与第六阶段之间的调用顺序、ModelCondition、迷雾、其他共享时间读者仍有独立风险。它不是跨帧率联机安全声明，也没有突破 90 FPS。

## 已有菜单与空闲对照

候选通过既有调度、加载、导出、特征及便携构建检查。私有菜单预检确认：90 FPS 的三处操作数均指向同一个逐位 30.0 常量并在采样期间保持；30 FPS 的三处完整原指令保持。构建检查和菜单预检不代替地图内动作验收。

## 诊断字段与早期失败

历史观察器把 Object 的 pending XYZ 和偏移 `0x236` 的四字节一起比较。原生消费路径实际读取 `BYTE 0x236`，只有它非零时使用 pending XYZ；对象构造会清零该字节，而 pending XYZ 可能尚未初始化。历史原始差异保留，但无效缓存差异不能直接称为模拟分歧。新的比较按有效字节处理。

动作诊断使用原生客户端输入流、原生类型化参数与本机玩家身份校验，观察两端自然执行入口与实际对象状态。它没有通过 Lua 直接修改模拟状态，也不强制调用 CRC。此前第二版诊断首轮原生 30 / 30 在状态文件访问失败时按原阈值停止；两端仅有两个公共 legacy CRC 点，跨度 450 帧。停止后发起过生产命令工具调用，但在写请求文件前因进程已经退出而拒绝；游戏日志没有该请求的解析、入队或执行确认。该失败保留，不能算作动作或联机验收通过。

该轮同时确认初始单位实际为盟军与苏联建造场，生产模块有两个不同的原生 key。字段和类型必须从真实模块确认，不能把旧命名或猜测值当作技能、生产就绪或生命值。

## 原生 v3 西侧 travel 失败后的独立战斗观察

run ID：`20261004-051226-922854-extonly-crossfps-native-native-hostA`。该轮西侧 staging 使用相对敌方建造场的 `dx = -200`。原自动场景的 60 秒 travel 超时后，另行发出了三条独立的首次攻击请求；这不是对原移动或排队请求的重试，也没有把原自动场景改写为完成。

原自动 14 条主请求与后发 3 条首次攻击合计 17 条，均在双方自然执行器有唯一、类型化参数一致、同逻辑帧的入口。另有 8 条选择消息作为辅助证据，不能混入这 17 条主请求。攻击消息自身携带玩家和目标；actor 身份需要结合此前的选择消息和本机受理证据，不能把未使用的 union 字段误当参数。

有限效果包括 MCV 打包、移动与展开，电厂和兵营出现，以及三名普通步兵 ObjectID 243 / 244 / 245 出生。三名步兵的 staging 移动进入执行器，但原 travel 必要条件未完成；后发三条独立首次攻击的双方共同执行帧分别为 6322、6342、6362。

真实生命值读取已针对该对象的原生 ActiveBody 合同核实：Object `+0x33C` 指向已识别的 body，其当前值与最大值来自已核实 getter 的对应字段；观察器只读字段，没有调用 getter。未知 body 类型或未核实偏移不计为生命值。

目标为 ObjectID 238、owner 3 的苏联建造场，最大生命值 5000。双方均观察到伤害，在逻辑帧 7723 / phase 6 的 coherent 记录中观察到生命值 0，并在同帧见到倒塌对象 **ObjectID 256**，模板为 `SovietConstructionYard_Collapse`、hash 56298937。随后在仍有其他对象的非空 mode 1 世界中观察到目标缺失，之后才出现 mode 9 空世界。后续空世界没有被单独当作死亡证据。

两端 observer 各有 2404 个样本，原结束状态为 `END_OF_OWNED_LIFETIME`，进程退出码和 observer 错误记录正常。这只是原持有生命周期结束，不是整轮状态通过。观察器从约 1752 / 1753 帧开始，晚于打包、MCV 移动与展开；389 个 postgame 空世界样本不计入活动对象状态覆盖。

严格同 `(logic frame, phase)` 比较有 20 个公共键、181 个对象比较，未记录投影差异；每端有 3 个非单调键行未纳入严格流合并，原始行保留。较弱的同逻辑帧、异阶段比较有 615 帧、4962 个对象比较，记录 **1358 项投影差异和 1 项存在性差异**。差异字段统计为 pending 有效字节 1333、有效 pending XYZ 1333、矩阵 270、生命值 22；字段可在同一对象重叠，不能相加为对象总数。阶段组合为 595 帧 3 / 6、1 帧 6 / 3、12 帧 6 / 6、7 帧 3 / 3。所有这些差异保留，不能删去后声称全量一致。

自然 phase 1 动作记录按 `(logic frame, actor ObjectID)` 比较，25056 项双方实际存在对象的有限投影未记录差异，13181 项双方缺失占位另列，8 个重复键歧义保留。这不是同一时刻的全世界原子快照。该轮可支持有限的生产、攻击、伤害与 coherent HP0 观察，不能成为完整状态或跨 FPS 安全声明。

## 候选 90 / 原生 30 的自动 17 动作

run ID：`20261004-052450-796702-extonly-crossfps-90-native-hostA`。A 端加载固定 SIMPIN 候选；B 端为原生 30、没有加载 FrameLab。B 端准备目录里的候选 manifest 引用不代表 B 端加载候选。

这轮使用同一固定 scenario v3 源码，事前规定建造场、电厂和兵营后三次各 30 秒自然等待，并把 staging 改为敌方东侧 `dx = +500`。它与上一轮原生西侧 `dx = -200` 的几何、自动攻击触发条件不同，不能据此声称 90 FPS 修复了原生 travel 失败、运行更快，或把这两轮当作只改变 FPS 的对照。

原场景结果为 `FINITE_NATIVE_ACTION_EFFECT_CHAIN_OBSERVED_BOTH_PEERS`：17 条自动主请求的有限必要效果在双方被观察到，不需要后发攻击。另有 8 条 reason 0 的选择消息，与 reason 1 主请求分开保留。

自动链覆盖打包、MCV 移动 / 停止 / 展开、电厂和兵营排队 / 放置、三名普通步兵生产、staging 移动，以及三条首次攻击。三条攻击的双方共同执行帧为 5743、5793、5836；所有主请求均以原生类型化参数和实际双方执行入口核对。

独立 observer 从约 A 帧 3982 / B 帧 3974 开始，已经晚于打包、MCV 移动、展开、电厂和兵营出现，但早于步兵出生。早期效果来自场景自身只读检查及自然 phase 1 记录，不能写成独立 observer 覆盖完整 17 动作链。两端各有 2302 个 observer 样本；原 footer 为 `END_OF_OWNED_LIFETIME`，observer 错误为空，1142 个 postgame 空世界样本排除出活动状态比较。

目标仍为苏联建造场 238、owner 3、最大生命值 5000。双方首次 coherent 伤害记录约为 4974.486328125，最低 coherent 生命值均为 **23.894521713256836**。随后双方在仍有其他对象的 mode 1 世界中观察到目标缺失与倒塌对象 ObjectID 256（`SovietConstructionYard_Collapse` 模板），之后出现 mode 9 空世界。

**该轮没有采到 coherent 生命值 0。** 对包含非 coherent payload 的全部原始 observer 样本另行只读扫描，每端有 1119 条已核实目标生命值记录，也没有当前值位模式为零的记录。不能用目标缺失、Collapse 或 postgame 空图补写 HP0，也没有独立死亡标志可据以宣称完整死亡合同。原生上一轮的 coherent HP0 与本轮未采到 HP0 的区别保留。
