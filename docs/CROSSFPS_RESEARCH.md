# 30 / 60 / 90 FPS 联机研究记录

日期：2026-10-04。本文属于 `research/cross-fps-lan-20261003` 的实验记录，不改变公开 `v0.2.1` 的验收结论。候选工件与公开发行物分别保存。下文区分自然执行入口、有限对象效果、严格状态比较、自然 CRC 和实际呈现测量；其中一项有记录，不代表其他项通过。

## 当前实际不同步与三开验证状态

候选仍未完成跨帧率联机验收。双端自然 AI 场景中，90 FPS 端与未加载 FrameLab 的原生 30 FPS 端交换房主后，运行 `20261004-121052-460909-extonly-crossfps-90-native-hostB` 实际报告不同步。双方完整自然 CRC metadata 对齐后的首次值差异在逻辑帧 **3375**：90 FPS 端为 `0444147D`，原生端为 `788F2F7E`。前一公共 CRC 帧 3330 相同；75 次公共自然 CRC 中有一次值差异，没有对应的 scalar、multiplicity 或缺失差异。异步只读对象采样没有覆盖首个分叉对象，尚不能据此归因到具体对象、死亡顺序或显示骨骼反馈。这个失败没有被此前房主方向的有限匹配覆盖，研究发行继续暂停。

后续按要求使用未经修改的 NewMap、两名凶残 AI、50000 开局资金，并使三个被动真人客户端进入同一局。原生三端对照 `20261004-141415-622013-extonly-crossfps-native-native-native-hostA` 的控制器和三个观察器正常退出，原始持有的子进程均已等待回收；正式入局前后分别核验实际地图、AI 难度及原生 GameInfo 的开局资金配置。自然 CRC 的 AB、AC、BC 三组配对各有 **51** 次完整 metadata 公共记录，覆盖逻辑帧 **45–2295**，值、scalar 与 multiplicity 差异均为零。300 秒是观察窗口；游戏较早结束，结束后的等待不算战斗或模拟帧覆盖。

冻结 V7 分析器最初拒绝三个世界日志的 header：预期关系矩阵中的 tuple 经 JSON 序列化成为数组，直接比较 Python 容器类型导致误拒。独立的 V8 只对正确的 JSON 结构做严格规范比较，仍拒绝错误指针、身份、跨端绑定、关系值、bool/float 混用与 false bounds；128 项独立检查通过，对象边界、自然 CRC、意图和流式事件等 15 个纯函数的 AST 与 V7 一致。原 V7 拒绝结果保留。V8 得到有限对象样本，但没有完整世界逐帧证明；原生三端也有少量 phase 3 矩阵与 pending 字段差异，生命值无对应差异，不能直接解释为锁步失败。

随后运行 `20261004-143257-180817-extonly-crossfps-native-60-90-hostA`：A 未加载 FrameLab，B/C 分别实读候选状态 60/90、ratio 4/6、mask `0x3ACFFF` 以及三个高度 pin 的成功安装；实际 NewMap、两名凶残 AI 与原生 50000 资金门分别核验。AB、AC、BC 各有 **83** 次完整 metadata 公共自然 CRC，覆盖 **45–3735** 逻辑帧，CRC、scalar、multiplicity 与缺失差异均为零。控制器、三个观察器及原始持有句柄收尾正常。600 秒是观察窗口，直接计数器的新鲜单调 mode 1 区间约 **267.8 秒**，之后游戏结束；getter 的区间实测约 27.67/55.36/83.02 Hz，与目标档位和实际 Present 分别报告。并行训练在启动阶段退出的外部报告作为负载条件保留，不据此归因帧率或战斗结果。

60 FPS 房主的三开 `20261004-144721-076224-extonly-crossfps-native-60-90-hostB` 正常收尾。AB、AC、BC 各有 **66** 次完整 metadata 公共自然 CRC，覆盖 **45–2970** 帧，值、scalar、multiplicity 与缺失差异均为零；其中 60 次 level 1、6 次 level 2。直接新鲜 mode 1 区间约 **211.8 秒**，300 秒观察包含结束后的等待；没有覆盖旧 3375 帧失败。原版对照的 51 次及 30 FPS 房主方向的 83 次也均包含 level 1 与 level 2，不能统称 level 1。

90 FPS 房主方向 `20261004-145729-079836-extonly-crossfps-native-60-90-hostC` **实际不同步**，启动器失败退出，三个观察器按原持有进程生命期结束并全部回收。完整 metadata 有 70 个共同自然键，覆盖 45–3150 帧；AB（30/60）全部一致，AC 与 BC 的首次值差异都在 **3150 帧 level 2**：A/B 为 `0CEFD49A`，C 为 `624939EF`。该次原生调用为 `004F1E07`、stream 0、a4 0、entry/exit mode 1 与 phase 1、cursor 9→0、lite 1 / deep 0；scalar、multiplicity 与缺失差异均为零。此前 3105 帧 level 1 的值 `7BE4D84A` 三端相同，上一条同 level 2 的一致记录为 2700 帧 `8471BA9C`。两个 level 的覆盖范围不同，不能把首个模拟字段变化限定在 3105–3150。此局实际本地玩家映射为 A→Player4、B→Player5、C→Player3，按原生本地指针和身份绑定核验，不能固定假设 ABC 对应 Player3/4/5。

现有异步投影没有首叉的完整对象序列化、MC 或武器状态，不能把附近矿车的 pending 有效位差异当成原因。旧 R5 原生 CRC trace 仅覆盖 0–900 帧且片段上限 32 字节，无法定位这一分叉。三个客户端的幸存录像字节另作带原始 owner、文件 stat 与 SHA 的私有保留，完整性未认证。录像头中三端均记载种子 `524700087`、NewMap 与五名参与者；头部解析不证明完整重放。两次真实失败均保留，跨帧率安全发行继续暂停。客户端 getter 计数不等于 D3D Present，尚无实际呈现率验收。

私有 R7 将自然诊断窗口扩到 0–6000 帧、片段上限扩到 512 字节，未改变 FPS 候选。原生三端对照 `20261004-154553-465079-extonly-crossfps-native-native-native-hostA` 已正常回收，地图、两名凶残 AI、50000 原生分配前后配置和实际玩家身份分别核实。三组配对各有 **61** 个完整自然 CRC 键，覆盖 **45–2745** 帧，55 条 level 1、6 条 level 2，差异为零；对应 61 个有限 Object scope 字节也一致。记录器的 IO、drop、overflow、truncation 计数均为零。实际 mode 1 计数前缀约 **178.6 秒**后游戏结束；A/B 观察器各600样本，C为599样本、299.525秒的原持有生命期前缀，不能把观察时间当成持续战斗覆盖。

随后用同一 FPS 核心运行 R7 的 90 FPS 房主三开 `20261004-155855-289436-extonly-crossfps-native-60-90-hostC`，启动器和三观察器退出0、所有原持有子进程回收。完整自然 metadata 三组各 **180** 个共同键，覆盖 **45–8100** 帧，162 条 level 1、18 条 level 2；CRC、scalar、multiplicity、缺失和非法值差异均为零。Object trace 仅有窗口内 **133** 个完整 scope 对，覆盖 **45–5985** 帧且字节无差；其后的 **47** 个自然 CRC 键保留对象字节未采集状态。有效 mode 1 直接计数区间约599.8秒，末帧约8126；A/B各1200观察样本，C为1199个生命期前缀。这次没有复现旧分叉，但不是修复验证：战斗序列不同，FPS 核心没有新修改。异步逐对象投影中，6983帧 phase5 的 Object977（AlliedBaseDefense）在B/C有实际Active HP差异850.0与286.6283569，最大值同为1000.0；此差异原样保留，同整数帧和阶段不保证同一原子时刻，不与最近CRC配对归因。

静态复核确认 R7 只采 Object 子树，level 2 的顶层 RNG 摘要、管理器和计数器贡献仍有缺口。它们经过现有原生 raw writer，正在独立实现 R8 的全局段记录和离线累加值账本；采集窗口拟扩到0–18000以覆盖本轮较晚区间，每次原生CRC和ring的固定预算保留。未知类不读取 Object 字段，未闭合栈、截断、stream 冲突或账本断点保留未知。诊断器的完整对象片段匹配不能代替全局 CRC 重建，亦不能取消已有不同步。原始失败、工具读取预算拒绝和异步世界采样差异分别保留；俩AI的伤害来源还须另有真实武器或发射／命中证据，现有Goal1意图记录不足。

R8 已实现并冻结，窗口为0–18000；源码、纯模拟及编译后函数体分别经过独立核查。实际原生三开对照 `20261004-170413-393193-extonly-crossfps-native-native-native-hostA` 在准备进入约175秒后开始记录游戏，约204秒时因 A 端状态读取互斥锁等待超时而停止，未完成300秒观察。启动器退出1、三个观察器退出0，所有原持有子进程正常回收。三组有限自然 CRC 各有11个共同完整键（45–495）且值与 metadata 无差，A另外有540帧记录；这个前缀不是整轮通过。

该次读取错误的实际字段为 `WaitForSingleObject`、返回258、等待约1.014秒。A端状态发布序号96的QPC证据显示，旧兼容副本的 `ReplaceFileW` 耗时约2.266秒，状态锁持有约2.272秒；读取等待窗口落在该持锁区间内。不是通过增加 freshness 或 mutex 超时来解决的问题。另有B端唯一 trace header 提前记载 install_state0/active0，随后却已有采集事件；独立分析保留其未知状态，不能以事件存在代替正确安装头。A/C的11个共同有界raw账本无累加值缺口且字节一致，仍不替代失败收尾或全状态证明。R8原失败及原日志保持，修正另用R9诊断身份。FPS核心尚未因此改变，旧3150/3375不同步继续未解决。

## 诊断字段与早期失败

历史观察器把 Object 的 pending XYZ 和偏移 `0x236` 的四字节一起比较。原生消费路径实际读取 `BYTE 0x236`，只有它非零时使用 pending XYZ；对象构造会清零该字节，而 pending XYZ 可能尚未初始化。历史原始差异保留，但无效缓存差异不能直接称为模拟分歧。新的比较按有效字节处理。

动作诊断使用原生客户端输入流、原生类型化参数与本机玩家身份校验，观察两端自然执行入口与实际对象状态。它没有通过 Lua 直接修改模拟状态，也不强制调用 CRC。此前第二版诊断首轮原生 30 / 30 在状态文件访问失败时按原阈值停止；两端仅有两个公共 legacy CRC 点，跨度 450 帧。停止后发起过生产命令工具调用，但在写请求文件前因进程已经退出而拒绝；游戏日志没有该请求的解析、入队或执行确认。该失败保留，不能算作动作或联机验收通过。

该轮同时确认初始单位实际为盟军与苏联建造场，生产模块有两个不同的原生 key。字段和类型必须从真实模块确认，不能把旧命名或猜测值当作技能、生产就绪或生命值。
