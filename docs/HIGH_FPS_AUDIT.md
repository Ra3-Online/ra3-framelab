当前候选为 `0.2.4-dev5-highfps5`，标题“高帧候选 5”。用户报告苏联 MCV 展开仍像 30 帧，并澄清铁锤坦克的问题是**整体位置移动不连贯**。本轮只读本地游戏映像、反编译文本和日志，修改源码并运行离线测试；没有启动、附加、注入或操作游戏。这里记录的是共用引擎路径审查，不是全兵种实机验收。

本轮修正了三处仍读取离散模拟进度的显示路径，同时补充按模型 / 对象的诊断。**目前不能宣称 MCV 展开或铁锤位移已经实机修好，也不能宣称 120–240 跨帧联机安全。** 铁锤的插值绕过标志、历史缓存和实际显示率需要同一次复测的对象级日志才能继续区分。

## 六个直接读点逐项处理

| 原生读点 | 已确认用途 | highfps5 处理 |
|---|---|---|
| `0x52F605` | Drawable 的位置三次插值和朝向矩阵插值 | 保留 highfps2：仅正常 `Drawable::update` 调用使用独立显示进度；初始化 / 未知调用保留原生读取 |
| `0x65522F` | 摄像机路径 / 关键帧插值 | 保留原生；不是本轮已定位的坦克位移路径 |
| `0x70F418` | 整数进度读取，含普通累计和结构展开分支 | 保留原生；调用语义混合，不能整体替换成依赖墙钟的值 |
| `0x8E823B` | 附着部件的骨骼 / 矩阵显示混合 | 新增独立显示进度读取，只替换一条 MOVSS，保留 EAX 引擎指针及其他上下文 |
| `0x8F3D8B` | 模型结构高度 / 显示变换的插值分支 | 新增独立显示进度读取，只替换一条 MOVSS，保留 ECX 引擎指针及其他上下文 |
| `0x8FB6D2` | 炮塔 yaw / pitch 显示缓存 | 保留 highfps3 的独立完成代号及显示进度；没有重新修改角度或瞄准逻辑 |

两处新原生读点只在高帧模式启用且引擎指针与本轮 owner 一致时读取 `g_highDrawAlpha`，其他情况回读原地址。原生加载的 MOVSS 会清零 XMM0 上三条 lane，适配器保留该行为，并保留 EFLAGS、通用寄存器、其他 XMM、x87 和 MXCSR。

另一个遗漏不在原生 PE 中：FrameLab 自己的 `fl_wrap_construction_progress` 在 mode 0 中仍直接读取共享 `engine+0x60`。高帧入口已经为模拟恢复了原生值，在显示预处理期间便会看到 0.5 / 1 等离散进度。现在 mode 0 的已知显示包装从私有显示缓存读取；mode 1、其他模式和禁用 / 空指针回退仍按原 ABI 调用原函数。该修正覆盖使用 StructureUnpack 显示进度的模型，不能假定所有 MCV 模型都采用这一模式。

## 整体位移、载具绘制和模型动画

| 检查项 | 证据与结论 |
|---|---|
| 通用位置更新 `0x52F500` | 正常调用位于 `0x53A792`，返回 `0x53A797`；初始化还有另一个直接调用，未放宽该调用的 alpha 条件 |
| 历史缓存 `0x5296B0` | 从对象的前一位置 / 当前位置及旋转形成显示历史；没有增加模拟位置写入 |
| 插值有效窗口 | 两处窗口继续为 `target/15+2`；165 为 13 个显示帧，覆盖每个逻辑周期约 11 次更新 |
| `Drawable+0x13E` 的 bit 4 | 会跳过原生插值。它来源于模板标志，不能在不知道具体单位取值时对全引擎清除；新增诊断只读此标志 |
| 通用矩阵 getter `0x528C60` | 只返回 Drawable 缓存矩阵；本身没有另一次插值调用。不能靠给此 getter 再改一个 alpha 解决问题 |
| 坦克绘制 `0x910180` / 虚表 `0xC62D30` | 进行履带 / 物理显示处理后进入通用模型绘制 `0x90F820`，继续使用传入显示矩阵；没有发现独立的整体 XY 离散位移读取 |
| 卡车绘制 `0x910230` / 虚表 `0xC62EB0` | 包含车轮、转向和附着显示，调用通用模型绘制；不能把轮子转动当成整体位移的验收 |
| 车身物理显示 `0x535DD0` / `0x532CA0` | 保留 30Hz 物理外观采样和中间帧混合；没有改逻辑位置、速度或随机数频率 |
| 模型动画推进 `0x90ECF0` | 循环、单次正向、反向、往返使用模型毫秒时钟；mode 7 使用结构展开进度。冻结、空几何、空动画及状态切换会影响实际覆盖 |
| 显示时钟 `0xCE1388` | 两个原生推进分支已有每显示更新的时间预算隔离；本轮没有再修改共享时钟、逻辑频率或调度批次 |
| 模型入口 LOD / 动画门 `0x90F820` | 保留原门。未把全部模型强制设为每帧更新；该做法有 CPU 代价，也没有证据说明它就是本次近景铁锤 / MCV 的原因 |
| 粒子、光团、纹理 / shader、脚本模型和摄像机 | 保留现有时间域修复；没有本轮逐资源实机结论。不得从一个位置读点推广为所有动画已经流畅 |

`W3DScriptedModelDraw`、TankDraw、TruckDraw 等名称来自映像注册 / 反编译线索。上表是函数与共用机制的覆盖说明，未将具体资源配置映射到每个阵营、单位和形态，更未验收所有模型的绑定、骨骼、履带、轮子、武器和阴影。

## 上游思路对照

继续对照 [SAGE-Unlocked a770379](https://github.com/TheeHorse/SAGE-Unlocked/tree/a770379e35bf814ae9a0954f192b96b60b800b33) 的 `FindAnimGate`、`FindTopple`、骨骼插值和车身物理显示处理。这是固定源码快照，不代表已经核对最新主分支的全部差异。

该快照将“全模型每帧更新”的 `offscreenanim` 设为默认关闭；注释记录了它未解决离屏飞机阴影的顿挫。Topple 修复只在物体正在倒下时清除静态模型的“不混合”位。对应到 FrameLab，本轮不全局关闭 LOD，也不清除所有单位模板 / Drawable 的原生标志；先记录用户实际载具路径。新增适配器、C++ 诊断和测试为本项目实现，未复制上游代码。

## 新日志如何定位下一次手测

保留 GUI 的“额外特效修复”勾选。`VISUALREAD` 给出骨骼、结构、mode-0 进度读取次数。`VISUALOBJ` 是在已有模型 prepare 回调中观察的固定容量记录：128 个槽，每个键最多探测 4 个槽；无动态分配、文件写入、扫描或计时器调用。它选择原生 TankDraw / TruckDraw、任意一条使用 mode 2 / 4 / 7 的模型轨道，以及位置历史端点不同的通用 / 脚本模型，避免把诊断限定为某一种载具绘制类。同一模型在同一显示更新只记一次，三条轨道都观察。容量满会增加 `auditOverflow`，不会修改游戏对象。

| 字段 | 用途及限制 |
|---|---|
| `template` / `drawable` / `module` / `type` | 区分模板、原生实例 ID、绘制模块和类型；保存的地址仅作为标识，日志线程不解引用旧地址 |
| `samples` | 此模型被观察的显示更新数；不等于 Present 或 GPU 帧数 |
| `rawSteps` | 原生对象位置三个 float 位型发生变化的观察数 |
| `visualSteps` | Drawable 缓存位置三个 float 位型发生变化的观察数 |
| `moving` / `held` / `maxHeld` | 历史端点不同期间，显示位置未变化的数量及最长连续次数；只是诊断线索，地形、停靠、加减速和特殊模型也会影响它 |
| `bypass` | 观察时原生“不插值”位被设定的数量；工具不会清除此位 |
| `modes` / `mask` / `clipSteps` | 三条轨道当前模式、累计模式位集和任一轨道帧值 / 模式变化次数；不证明实际蒙皮或屏幕像素变化 |
| `stampSteps` | 模型上次更新时间戳变化数；可区分动画推进受阻与位置路径问题 |

输出仍由现有 GUI 定时状态查询完成。记录仅观察到达 prepare 的模型，跳过入口的模型、其他类型、表溢出、多个模块和对象生命周期复用会限制覆盖，不能用“日志没有该对象”宣称对象没有问题。

手测建议：165 档，先只造一辆铁锤并让它持续直线行进、转弯、停止，再单独观察苏联 MCV 展开 / 收起。对照原版 30，顺带确认围墙首显、苏联 / 帝国光团、炮塔和右键速度。退出游戏后保存本局完整日志。开发者结合相邻状态采样比较 `rawSteps`、`visualSteps`、`bypass`、轨道变化和实际更新率；如果位移仍不连贯，继续以该对象数据定位，不把此候选标成已修复。

## 验证与联机边界

离线测试执行实际编译的适配器、mode-0 包装和固定容量观察器，覆盖 120 / 165 / 240 的原生预处理调用顺序、其他 owner / 禁用回退、mode-1 透传、完整寄存器 / 标志契约、模拟字段不写入、正常与阶梯位移的诊断区分、重复绘制、实例 ID 复用、溢出、14 个高帧必需点的缺失 / 重复 / 冻结前漂移、安装读回及故障回滚。另运行原生映像特征 / 合同、导出、便携依赖和 GUI 离线测试。具体计数与构建日志随候选保存在本地。

最终离线四项检查：调度 95、视觉 1393、加载 48、安装合同 542，共 2078 项通过。额外原生高帧合同 68、原生视觉合同 30；两秒 165 档的旧离散读法变化 62 次，新显示读法变化 330 次。它们是拥有内存上的适配器 / CPU 逻辑检查，不能换算成真实游戏显示或联机结论。

本轮没有改调度器、批次、网络 CRC、逻辑位置、移动速度或模拟时间；这降低了触及模拟的范围，**不等于已证明跨帧联机安全**。新 DLL 的 30/165、90/165、165/240 等组合仍需独立自然 CRC、完整日志及长局验证。旧 visual6 的 30/60/90 记录不能替代新高帧候选的结果。
