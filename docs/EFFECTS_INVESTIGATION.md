## 独立施工诊断及未获支持的假设

在独立用户目录与无自动 FPS 代理的私有游戏副本中，使用已有 `90FPT Test.RA3Replay` 做有界回放诊断。保留创建进程的原始句柄、PID、创建时间、输入文件哈希与采样记录；只对自行创建的进程安装探针和结束进程。正式 GUI、发行 DLL、用户游戏文件均未被本次诊断改写。探针只观察原版函数参数和状态，修正模式一直为 0；不作新的联机安全结论。

原版 `StructureUnpackUpdate` 显示进度函数 `0x006F6CB0` 把当前帧减起始帧的结果按无符号数转换，确有“若差值为负则钳到 100%”这一静态候选问题。但实际 90 回放记录 26,176 次有效计算，30 回放记录 5,482 次，负差值均为 0。因此尚无证据把本次闪现归因于进度下溢；后续视觉候选增加的保护不能据此当作根因已确认。

第二个 90 诊断观察 `0x0053F080` 的首次场景对象绘制：140,970 次调用、49 个首次观察对象、无表溢出；这些对象首次绘制时均没有待应用的模型状态标志，Drawable 与逻辑对象的 60 字节 ModelCondition 一致。这个回放没有复现手动放置围墙的闪现，也没有证明手动放置路径不存在初始化顺序问题。后续使用可重复的手动操作；不以原视频对应的 `.RA3Replay` 为前提。

90 回放的显示帧计数约每秒推进 90、逻辑帧约每秒 15；这只是引擎计数，尚非 GPU 呈现验收。30 对照中存在长时间计数停住，原因未确定；两臂墙钟进度不同，不能拿总运行时间直接判断补丁增加了卡顿。进度环只保留前 2,048 项正值及后续负值，计数覆盖所有进入该计算的调用；首次对象表容量 4,096、记录上限 1,024。未进入计算的未初始化模块和没有对象绑定的预览不在第一探针范围，不能将“负值为零”外推到所有放置路径。

## 对照 SAGE-Unlocked 当前源码

比较固定于 [87d2481217379fe0592e020cdaf2b7ca0e94910d](https://github.com/TheeHorse/SAGE-Unlocked/tree/87d2481217379fe0592e020cdaf2b7ca0e94910d)，对应 2026-10-07 的 v1.9.4；此前报告第 5 节对 v1.6 的比较保留其历史范围。

作者的[粒子闪烁调查](https://github.com/TheeHorse/SAGE-Unlocked/blob/87d2481217379fe0592e020cdaf2b7ca0e94910d/docs/TECHNICAL.md#how-i-found-the-flicker)采用 apitrace：捕获 D3D9 调用，重放导出连续帧，比较闪烁帧与相邻正常帧，再逐 draw call 定位。其样本定位到水面反射中的 GPU 粒子，CPU 顶点出生时间在 120 帧下为 shader 时钟的四倍，产生负粒子年龄，放大尺寸与颜色。这个测量比单纯修改粒子更新次数更能直接验证原因；它是上游样本的证据，尚不是本地苏联光团的测量。

其核心修复是保留以 30 帧为单位的粒子时钟，并只将粒子模拟调用门控到 30 Hz；同一更新函数的绘制桶必须每个显示帧重建，以免留下陈旧指针。上游文档地址主要基于 Steam 1.13，不能直接作为本地 1.12 的补丁地址。[源码入口](https://github.com/TheeHorse/SAGE-Unlocked/blob/87d2481217379fe0592e020cdaf2b7ca0e94910d/src/Unlocker.cs)为 `FindPacingSites`、`FindParticleSim` / `ThrottleParticles`、`FindBlinks` 和 `FindPulse` / `PatchPulse`。

| 路径 | 本地 FrameLab | 上游及本轮判断 |
| --- | --- | --- |
| GPU 粒子出生时间 | P4 将 `0x006C17CA` 的帧/毫秒乘数单独指向零售 `0.03f` | 上游不重定向生成这类时间单位的初始化；两者都保护 30 帧单位，不能仅因本地共享 `CDBC5C` 变为目标值而断言漏修 |
| GPU 粒子过期时间 | 不修改原帧率整数，P5 保持读取零售 30；安装前核对操作数 | 上游也保留游戏自己的原帧率整数 |
| 粒子系统与 CPU 粒子 | 勾选额外特效时，`FL_G_PSYS` 仅包装 `0x005F43AD -> 0x006D1D30` 模拟调用；显示桶仍每帧重建 | 上游同样只节流模拟调用；本地状态接口可报告请求但未安装，以及实际放行比例 |
| GPU shader 时钟 | 原版 `Time` 经 `sub_99BF90` / `sub_99E4F0` 设置；原版粒子毫秒时钟与该时钟均由游戏累计时间推进 | 已核对原版路径；本轮未捕获实际 shader 常量与粒子顶点，因此不能把静态一致性视为绘制验收 |
| Drawable 脉冲 | 本地 Tint 修正涉及颜色包络、脚本闪光；没有上游相同的单独 pulse 门 | 原版 `sub_532AC0` 每次调用递减 `+456` / `+476`，从客户端帧求正弦并写 `+460`，还有显隐处理；上游对 Drawable 更新中的这一调用及正弦时钟分别处理。它是待审计差异，尚未证明控制截图的橙色粒子光团 |

上游[建筑特效 issue #4](https://github.com/TheeHorse/SAGE-Unlocked/issues/4)在本次查阅时仍开放；作者称 1.8.1 中发电厂烟雾看起来正常，等待确认。烟雾、Drawable 透明度和橙色粒子光团不能按名称合并成同一个已修问题。

## 本轮已实现的启动防护

GUI 在启动游戏前检查实际 `.game` 文件所在目录。仅当 `d3d9.dll` / `dinput8.dll` 含有完整、以零结尾的 ASCII 或 UTF-16 `CnCFpsUnlocker.dll` 引用，且对应 DLL 存在时，明确拒绝叠加。不会因为发现任意 `d3d9.dll` 就拒绝 DXVK、捕获器等其他代理；不会加载第三方 DLL，也不会移动、删除或改写游戏文件。文件读取设 64 MiB 上界，无法读取时明确失败。

新增只读命令，不启动游戏、不注入或提取 FrameLab DLL：

```powershell
.\Ra3FpsTest.exe --check-conflicts "<游戏目录>"
```

退出 0 仅表示没有发现上述已知组合，不是完整兼容性保证；退出 1 表示已知组合或检查失败，退出 2 表示输入不正确。运行时仍须校验原基准、完整特征和安装状态。仅将另一工具的 ini 改为 30 并不卸载它的其他代码补丁；复测应使用只加载一种工具的独立游戏副本，或按该工具说明关闭自动加载。

真实 GUI 的 13 项离线场景测试覆盖 ASCII / UTF-16、非对齐字符串、中文和空格路径、Data / 平铺布局、普通代理、缺少伴随 DLL、残缺引用、错误目录、超大文件、读取失败，以及 `--auto` 在创建游戏进程前拒绝。每次检查核对输入字节未变、没有安装成功日志，也没有提取补丁 DLL。实际配置的只读检查也识别了冲突并返回 1。调度、错误宿主加载、模拟合同分别为 54 / 48 / 208 PASS、0 FAIL。
