# Ra3 FrameLab 技术报告：90 FPS 基线、便携化与 240 FPS 对照

公开基线报告日期：2026-10-03；研究预发行补充：2026-10-05；最新视觉候选补充：2026-10-09。公开基线为 0.2.1，当前源码为 **0.2.3-dev1-visual5**。本报告区分源码机制、离线验证、历史实机与有限覆盖；0.2.2-dev1 矩阵见 [跨帧率记录](CROSSFPS_RESEARCH.md)。visual1 选择卡顿得到用户确认，visual2 / visual3 视觉手测失败。visual4 的 12:14–12:17 有效 90 帧手测中，用户确认苏联电厂、矿场光团正常，围墙闪现仍在；五顶点修正 855 次、跳过 0 次，施工同戳补算 0 次。visual5 新增默认墙件首显保护，尚待手动画面与联机验收。完整证据和上游对照见 [画面调查](EFFECTS_INVESTIGATION.md)。

visual5 的四个新增站点为默认几何创建调用 `0x90D5E8`、几何入场调用 `0x90CDD5`、原模型条件接收入口 `0x90CE60` 和原绘制透明度调用 `0x90FA63`。登记发生于世界 owner 绑定前，使用 ThingTemplate 的类型 / 实例 ID 和已写入的原生创建旗标识别活墙件 / 预览。入场保持原始 scene / shared-reference 参数及返回，只有待初始化墙件的几何 alpha 暂置零；正常透明度计算照常执行，未初始化墙件返回零倍率，原生透明度分类随后正常运行。MC 跳板只重放已核对的五个入口字节（124 字节局部栈、保存 EBX / EBP），跳回 +5；原函数全部返回后，确认状态字段与输入的 15 个 DWORD 相符才解除保护。不调用额外 MC 或场景注册，不持有引擎引用，也不使用显示帧数等待。其目标是覆盖初始默认模型先于施工状态可用的高帧率显示窗口；现有视频 / 日志尚不足以断言该窗口就是用户异常帧的唯一原因。

visual4 保留 GPU 构造 `0x6D2640 → 0x6C1770`、顶点上传 `0x6C6C91 → 0x6B99D0`、显示施工进度 `0x6FD596 → 0x6F6CB0` 和绘制前 `0x90F8A3..0x90F8B6`。零售光团的 GPU 几何类型为 2，原表 `C19244[2]=5`；五个 40 字节记录中的可见寿命改为 15.75，池寿命留到 16，出生不改，并核对原 writer 的结束指针。visual3 错误要求 4，真实上传全部跳过。施工进度继续只读逻辑时间与引擎插值；撤回提前调用 W3D 条件接收函数。模型状态切换原生写当前动画时间戳，绘制时会跳过同戳计算；仅在已选中施工条件、存在 MATCH_UNPACKING 轨道、原初始帧哨兵或原 restart 尚未消费且未冻结时，查询仍在进行的显示进度，再调用原动画函数。模型 / 模拟时间、世界队列及必需相位门不在此处理改写。该初始姿态路径有静态证据，尚无新画面命中；原 W3D 更新仍有自身副作用，新 DLL 需要重新实测画面和联机。

## 2. 受支持镜像与固定地址的性质

离线验证基线：2009 构建、32 位 PE、RA3 1.12，9,306,120 字节，时间戳 `0x4A53BB67`，SHA-256：

```text
e212791928aca4fc3898c6af28f9081ffa28fc3758b009b44479037429f3b1fc
```

镜像摘要标识测试输入，不等同于运行时完整文件摘要白名单。DLL 在运行时检查模块、PE、特征匹配、预期操作数及帧率数值；签名缺失、歧义或上下文不符应拒绝安装。撤销表为 128 项。`0.2.2-dev1` 在写入失败后尝试恢复原字节及原页保护，复读核验；任何恢复失败保留完整撤销记录与失败状态，阻止再次安装，后续 Disable 可以重试恢复。错误 30 不代表已经完全恢复，也不保证运行期间卸载安全。

引擎首选基址 `0x00400000`、固定 VA、字段偏移及 opcode 属于这个游戏版本的内存布局契约。将它们当作“本机硬编码”删除会破坏校验。涉及的主要时间数据包括：

| 引擎位置 | 原版含义 | 注意事项 |
| --- | --- | --- |
| `0xCAF9D0` | 逻辑频率 15 | 调度倍率的基线 |
| `0xCAF9D4` | 客户端频率整数 30 | 优先重定向特定读者；实验 FPSGLOBAL 不代表安全修复 |
| `0xCE176C` | 客户端推进毫秒整数 | 有多类读者；隔离视觉时钟推进点 |
| `0xCE1388` | 游戏时钟累计值 | 诊断尺子读此值 |
| `0xCDBC50 / 54 / 5C` | FPS、毫秒/帧、帧/毫秒 | 共享浮点派生量，现有修正仍有模拟侧读者风险 |

同名 1.12、重新封装、不同年份构建或其他补丁叠加不能仅凭版本名确认兼容。测试输入、实际加载基址和特征结果都应留下记录。

## 3. 为什么当前上限为 90 FPS

引擎在一个 15 Hz 逻辑周期中组织六个阶段。现有 [schedule.h](../src/schedule.h) 以客户端帧序号和倍率 `r = target / 15` 计算每帧应完成的阶段总量和插值系数；运行时补丁仍无条件先推进一个阶段。

| 目标 | 一个逻辑周期的显示帧数 | 当前状态 |
| --- | --- | --- |
| 30 | 2 | 基线档位 |
| 60 | 4 | 支持，部分显示帧执行多个阶段 |
| 90 | 6 | 当前支持上限 |
| 120 | 8 | 需要允许零阶段推进帧 |
| 240 | 16 | 需要零阶段推进、独立显示进度及更长窗口 |

倍率要求为整数且不超过六。仅放宽 `r <= 6` 无法突破这个结构：同一阶段需要承载多个不同的显示帧，阶段号不再能唯一代表显示进度；无条件阶段加一也会使逻辑速度跟随显示帧率。

现有视觉时钟累加器用整数余数分配 `1000 / target` 毫秒，避免逐帧整数截断造成漂移。它校正的是视觉时钟推进，不是限帧器睡眠预算。现有算法仍依赖实际显示率接近目标；性能不足时不能据此保证墙钟游戏速度不变。

## 4. 当前补丁组合与实验边界

CLI 默认组为 `0x28FFF`。`0.2.2-dev1` GUI 基础组为 `0x2CFFF`，默认车身探针、30 Hz 门和插值合计 `0x380000`，最终 `0x3ACFFF`；历史联机矩阵使用这一组合。当前视觉候选移除基础组中的 `0x4000` 动画诊断探针，GUI 基础组为 `0x28FFF`、默认合计 `0x3A8FFF`；额外特效与卷屏同时勾选时为 `0x1FFA8FFF`。比较数据须记录实际掩码。

GUI 额外特效勾选包为 `0x1F400000`，默认未勾选，包含帧时长、曳光、图标、粒子系统、镜头和 Tint 相关修正。公开 `v0.2.1` 的显式 SIMPIN `0x20000000`、SIMGATE `0x40000000` 请求默认关闭。当前候选在高帧率修改共享 DER_FPS 时，自动要求三处逻辑高度读者改读逐位 `30.0f`。`0.2.2-dev1` 在规范零售 30、逻辑 15、倍率 4/6 的 60/90 目标下，不依赖请求掩码而要求三处相位门；其他零售或逻辑基线的 60/90 拒绝安装。30 FPS 和 measure 模式不增加相位门。具体条件与安装核验见 [研究机制说明](CROSSFPS_RESEARCH.md)。

相位门读取引擎`+0x58`中上一个客户端帧结束时已完成的阶段。原生30把六阶段分成两批，正常客户端帧边界落在阶段3、6之后；60/90增加了阶段之间的客户端帧，不能让原来的延迟模拟工作随这些额外边界重复执行。ModelCondition同步与变换冲刷在阶段3、6边界放行，销毁请求在阶段6边界消费；初始值与原生空转状态另行放行。销毁包装仍调用原目标处理其他工作，只在非销毁边界暂存请求位、调用后并回，不能概括为跳过整个销毁函数。

dev1 的60/90安装必须同时确认三处调用、原目标、完整预映像及写后映像；掩码没有`0x40000000`也不能绕过必需门，DryRun同样检查该合同。GUI/CLI以新增必需状态位核验实际安装，旧值11不满足新合同的15。安装诊断证明的是三处门已按候选合同安装，不直接证明游戏业务语义或联机安全。

| 机制 | 实现目的 | 证据与限制 |
| --- | --- | --- |
| 视觉时钟两条推进分支 | 避免只修一条造成残余动画加速 | 特征和纯算术已检查；掉帧仍需墙钟验收 |
| 车身 30 Hz 门 + 插值 | 每显示帧递推的弹簧 / 姿态保持原版节拍 | 纯逻辑测试与历史实机反馈；边界换运动器仍需复核 |
| 迷雾与网络 skip 相位 3 | 保持两处条件配对及刷新顺序 | 代码修正，不代表敌方可见性问题已彻底解决 |
| 撤掉 R4 淡入构造器重定向 | 避免目标帧率初值与原版淡入计数域冲突 | 默认行为修正，不能据此断言所有透明度路径正常 |
| SIMPIN / 自动高度基准固定 | 三处逻辑侧高度读取保持原版 30 | 公开基线显式请求默认关闭；研究候选在上述高 FPS / DER_FPS 条件下自动必需。三处实际命中及状态对账仍需按场景验收 |
| SIMGATE | ModelCondition 同步、变换冲刷、销毁按模拟边界执行 | dev1 的规范 60/90 自动必需；三处完整特征、原目标、重叠指令窗口及完整写后映像核验；13局有限矩阵和保留未知见第1节 |
| 高帧率跳过 P7 组 | 阻止已知危险动画次数门实验 | 请求 P7 且目标高于原版帧率时，仅跳过该组，其他组照常安装；不是整套拒装或联机兼容证书 |
| 128 项撤销表 | 完整记录额外特效包超过旧 48 项容量的写入 | 防止安装时容量不足后整体回滚 |

“逻辑帧率 15 Hz”是必要检查，不足以证明逐逻辑帧的状态完全一致。共享浮点 FPS 读者、迷雾、对象生命周期、随机数消费与递推次数仍可能改变结果。

控制与查询接口在修改配置或检查状态之前取得同一 SRW 锁，避免同一 DLL 内的并发 Enable、Disable、DryRun 或时钟自检相互污染。成功安装后保存 target、ratio、请求掩码及实际 pin/gate 合同；已安装或未恢复时不能通过 SetGroups 改变运行掩码。线程冻结在枚举、打开、挂起或容量不足时拒绝继续写入，但不构成新线程创建、异常终止或运行期间卸载的完整并发证明。

当前 dev1 的本地构建通过 54 项调度、48 项非游戏加载与 208 项自有内存合同检查。合同测试在测试程序自身的数据页上调用实际解析、核验、写入与还原函数，覆盖缺失/歧义特征、错误目标、重叠窗口、第二/第三处失败、写后差异和页保护还原；不执行游戏包装函数或模拟游戏战斗。专用测试 PE 数据节先由 loader 映射，触碰前核验完整数组边界、MEM_IMAGE 和主模块所有权；避免普通私有分配已经占用固定模拟地址。链接布局或系统强制重定位不满足合同就明确拒绝运行。离线检查及这组自有线程检查不能替代实机联机。

### 私有 R12：独立 CORE 捕获与有限实测

R12 是私有验证采集器的改进，不是FPS调度算法，也不属于公开发行包所需的运行依赖。旧 UI 域继续保存其真实捕获时间和完整界面状态；新 CORE 域使用独立命名映射、身份绑定与捕获线程，只提供gameplay监控所需的逻辑帧、mode及原有CRC/desync摘要。进入房间、地图、角色、初始资金与READY界面仍由UI/原生门核验，新CORE的新时间不能替旧UI数据补新鲜度。

新线程以250ms为轮询目标，直接有界读取GameLogic根、`+0x50`逻辑帧、`+0x148`模式的开始与结束边界，并保存现有CRC/desync原始标量。该路径不调用引擎getter、不扫描对象、不执行UI路径或文件IO；目标间隔不构成Windows调度的硬实时保证。发布保留实际捕获开始tick、结束tick、QPC与owner epoch，TTL从真实捕获开始计算，不通过缓存重打时间。稳定根、完整读取、同mode1且逻辑帧正常前进可以是fresh；同frame/mode的coherence另列，fresh并非完整世界原子快照。

TTL仍为10000ms，传输竞争或已明确资格的捕获转换共用原gameplay累计2000ms缺口预算；恢复不会清零预算，也不追加in-call重试或缓存成功。读取失败、源错误、错误owner、真实TTL超限继续失败；原始正desync优先触发停止。正常postgame要求开始/结束均为mode9/frame0、独立直接计数为0，并满足原连续三轮0.2秒观测条件，不能由一次空世界或一次过期UI状态推断。R12已完成代码与独立编译复核，第1节列出的13局均已结束；它避免沿用旧UI状态判战场新鲜度，没有取消TTL或抹去UNKNOWN。跨机器、无私有诊断DLL、完整状态、全部视觉场景和实际Present仍未验证。

## 6. 可移植整理

构建脚本通过 VS discovery / VsDevCmd 获取 x86 MSVC 和 SDK，Python 来自环境或 PATH。仓库路径取自脚本所在目录，构建输出由 `FLAB_BUILD_DIR` 覆盖。资源在本次构建目录暂存后编译，GUI 内嵌的是本次 DLL。依赖检查从实际PE提取RCDATA / 101完整资源，将全部字节及SHA与独立DLL比较；相同版本文字但载荷不同、非法资源边界或多个语言造成歧义时拒绝。发行打包使用已有构建时仍执行该检查，避免只比较中间片段漏掉旧内嵌DLL。

2026-10-08 发现 GUI 启动清单注释含非法连续减号，Windows 在进入 GUI 主函数前即以“并行配置不正确”拒绝加载；应用程序事件日志的 `SideBySide / 59` 指向内嵌清单 XML 语法错误。`rc.exe` 可以成功嵌入无效 XML，因此此前编译、系统 DLL 导入和内嵌载荷检查通过仍不足以证明 GUI 能启动。`0.2.2-dev1-gui-fix1` 修正注释，并在资源编译前使用 SDK `mt.exe` 校验清单；最终 PE 的 `RT_MANIFEST / 1` 使用同一有界资源解析器提取并检查 XML，Windows 上再调用 `CreateActCtxW` 解析实际启动资源。该检查不启动 GUI、不加载补丁 DLL、不附加游戏，Windows 以外的离线检查会明确跳过激活上下文解析。实际启动验证另行记录，不能由离线检查替代。

修复包使用与原候选相同的 GUI 程序源码重新编译，将已完成矩阵测试的原 DLL 内嵌；DLL 完整 SHA-256 为 `9b500e2fa1e4e808cd646cb4ed62172305bea57a33022353bbe9e60a60e01d46`。通常从源码重建会因 DLL 中的编译日期、时间产生不同二进制摘要；修复包特意复用冻结载荷，并再次执行载荷完整比对与离线加载自检。本次没有新的游戏或联机测试，既有矩阵结论及 UNKNOWN 记录保持原验收范围。

开发探针使用显式游戏目录、唯一或指定 SkuDef、显式回放及 PID。测试回放副本生成唯一名称并检查摘要；bisect、verify 和 desync_capture 按运行创建隔离输出目录，避免旧截图或 dump 污染新比较。其他探针采用参数指定或构建目录下的默认日志文件，重复运行可能更新这些文件。IDA 输出是使用者配置，缓存随当前输入区分。

CLI 使用 `LoadLibraryW` 及 Unicode DLL 路径，DLL 的主日志和黑匣子通过 UTF-16 文件 API 写盘。诊断的 `char*` 路径接口明确为 UTF-8；ASCII 兼容。GUI 可以用 `FLAB_RUNTIME_DIR` 指定可写运行目录。

旧本机交接、个人账号路径、跨仓协调记录和重复旧快照原件保存到发布树外；正常 Git 历史保留。当前源码与发行包不依赖这些资料。源码包按明确目录与扩展名收集，不包含游戏、回放、日志、缓存或本机归档。

## 8. 继续突破 90 的验收路线

1. 先独立实现墙钟调度与状态机，支持零阶段显示帧、多阶段追赶、网络阻塞及暂停恢复；关键特征不完整应整体拒装。

3. 重审共享 FPS / 时长读者，用模块内时间单位替代不必要的共享修改；同时处理掉帧下视觉时钟、粒子、悬挂、建造、镜头节奏。
